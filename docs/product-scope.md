# Plex 产品范围与实施顺序

状态：初版设计草案。已确认产品方向；平台、模型接入和技术实现细节仍可调整。

2026-09-12 更新：第一阶段工程骨架已落地，实际实现与验证边界见 `docs/implementation-status.md`。

## 已确认的方向

Plex 是一个通用桌面 Agent。用户通过自然语言提出任务，Agent 根据任务选择工具，结合执行结果继续处理，并交付可检查的结果。

本地文件处理是第一个完整验证场景。产品架构需要支持后续扩展至代码、命令、网页与外部服务。

用户已确认使用 Bun 作为 JavaScript/TypeScript 的统一工具链和 Agent 运行时，覆盖包管理、开发脚本、测试与构建，Sidecar 同样使用 Bun。

用户已确认界面采用接近 Codex 的风格，并要求模型配置支持多个供应商。供应商与模型目录通过 models.dev 获取，支持分别配置 Key 和选择思考强度。

## 核心体验

- 用户创建任务，指定可访问的工作目录，并描述目标。
- Agent 可以读取上下文、选择工具并连续执行多个步骤；缺少关键信息时向用户提问。
- 界面展示回复、实际工具调用、执行状态、审批请求和结果文件。
- 用户可以批准或拒绝待执行操作，也可以取消任务。
- 任务结束后，用户可以检查产物、继续对话并查看历史记录。

界面展示执行摘要与可核查的工具记录，不要求模型输出内部推理过程。

## 能力路线

### 第一阶段：通用执行基础与文件任务

- 聊天和任务列表，支持流式回复。
- 选择工作目录，建立任务可访问的文件范围。
- 工具支持列目录、搜索文本、读取文本文件，以及审批后创建或修改文本文件。
- 同一任务可组合多次工具调用，并根据中间结果调整后续操作。
- 修改文件前显示目标路径与差异；拒绝审批后反馈结果给 Agent。
- 支持取消当前运行，保存消息、工具调用、审批记录与产物位置。
- 模型连接参数与密钥配置。第一版通过 models.dev 提供供应商与模型目录，按供应商保存密钥，并支持选择模型的思考强度。

首版文件能力以文本为主。PDF、Word、表格等格式通过后续解析和生成工具扩展。

### 第二阶段：扩大任务覆盖

- 受约束的命令执行，覆盖脚本、代码处理与开发工具。
- 网页检索、页面读取与带来源的资料整理。
- MCP 工具接入，支持外部服务与专用工具。
- 常用任务的可复用指令与工具配置。

命令执行、网络访问和外部服务写入分别定义权限。工具接入后继续沿用任务、审批与记录机制。

### 第三阶段：复杂工作流

- 浏览器交互与更丰富的桌面操作。
- 后台任务、定时任务与明确的中断恢复策略。
- 按实际需求引入多 Agent 协作。

这些阶段是建议顺序，尚未构成全部功能的实现承诺。

## 执行与权限约定

- Agent 通过已注册的工具获得能力；工具具备输入结构、执行函数、权限说明和结果结构。
- 文件访问校验由工具执行层负责，覆盖越界路径和符号链接。
- 首版允许读取授权目录内的文本；创建和修改文件需要审批，删除文件暂不提供。
- 审批绑定具体工具、参数、目标和拟写入内容。修改目标或内容后需要重新审批。
- 写入前重新检查目标状态；审批期间文件发生变化时，重新生成差异并申请审批。
- 取消后停止发起新的工具调用，并尝试中止正在进行的模型请求与工具操作。已完成的修改保留记录。
- 密钥不写入普通会话记录、日志或前端持久化存储。
- 工具结果与导入内容作为任务数据处理，不能自行扩大权限。
- 任务历史持久化与自动恢复执行分别设计。首版异常退出后，将未完成任务标为中断，允许用户查看记录并重新发起；自动恢复待后续实现。

## 推荐架构与实现状态

- Tauri 2：桌面窗口、系统对话框、应用生命周期与本地进程管理。
- React + TypeScript：任务、对话、工具记录、审批和设置界面。
- Bun Sidecar + OpenAI Agents SDK TypeScript：智能体运行与工具调度。
- SQLite：保存任务、消息、工具记录和审批状态。

数据流：界面 → Tauri IPC → Bun Agent 运行进程 → 模型与工具；执行事件沿原路返回界面。

Bun 选型已确认。上述架构已在首版实现中采用：Tauri、React、Bun Sidecar、Agents SDK 与 SQLite 均通过本机类型检查、测试和开发态启动验证。真实模型调用、安装包签名和跨平台分发仍待验证，详见 `docs/implementation-status.md`。

## Bun 开发、构建与分发

- 依赖管理：使用 `bun install`，提交 `bun.lock` 以固定依赖解析结果。
- 开发与脚本：使用 `bun run` 作为统一入口；Agent 直接通过 Bun 执行 TypeScript。第三方 CLI 必须检查实际运行时，必要时使用 `bun run --bun` 或 `bunx --bun`。
- 测试：JavaScript/TypeScript 单元及集成测试优先使用 `bun test`；Rust 侧测试使用 Cargo，界面与打包验证按实际需要选择工具。
- 前端：由 Bun 脚本启动开发和构建流程，具体构建工具待初始化时确定；最终界面在 Tauri WebView 内运行。
- Agent 分发：优先通过 `bun build --compile` 生成包含 Bun 运行时的 Sidecar 可执行文件，再由 Tauri 随安装包分发。目标是终端用户无需单独安装 Bun 或 Node.js，具体资源和依赖打包方案待验证。
- 桌面构建：通过 Bun 脚本调用 Tauri CLI；Tauri / Cargo 负责 Rust 编译及平台安装包生成，仍需对应平台的原生构建工具。

实施时先验证 SDK 模型调用、工具调用、流式事件和取消在 Bun 中的行为，再检查编译后的 Sidecar、SQLite 依赖、资源路径、进程生命周期与目标架构。后续引入 MCP 时验证子进程兼容性。发布前验证签名和安装包运行，避免将开发态运行成功视为分发验证完成。

若遇到兼容性问题，优先调查 Bun 下的修复路径，并记录证据；运行时选型调整需与用户讨论。

## 第一个验收任务

用户选择包含若干 Markdown 或文本文件的目录，提出：

> 阅读这个目录里的资料，整理一份项目概览和待办清单，写入 summary.md。

验收条件：

1. Agent 自主列出和读取所需文件，完成多步工具调用。
2. 界面显示真实执行状态与工具结果；失败时提供可理解的错误。
3. 写入前显示 summary.md 的完整新增内容或修改差异。
4. 拒绝审批时文件保持原状；批准后正确写入。
5. 越出授权目录的访问被工具层拒绝。
6. 取消任务后不再启动新工具调用，最终状态可见。
7. 重启应用后可以查看历史记录与产物位置。

## 开发前的默认假设

以下假设用于收敛原型，可随用户反馈调整：

- 优先验证当前 macOS 环境，其他系统随后验证。
- 第一版面向个人本地使用，由用户配置自己的模型 API 凭据。
- 应用关闭并退出后停止执行；后台运行和自动恢复暂缓。
- 首次运行模型需要联网；发送给模型的文件内容可能离开本机，需要在连接配置与任务授权中清楚说明。
